# Hazard warning database

Apply the migrations in order before using the DMC warning workflow. Run them from the Supabase SQL Editor or with the Supabase CLI (`supabase db push`) after linking this project. The second migration removes the latitude and longitude columns from databases that already applied the initial schema. The third migration adds current water, rainfall, and slope values to hazards. The fourth drops the obsolete `hazard_readings` table if it exists. The fifth adds `review_status` and seeds mixed review outcomes. The sixth adds `image_url` for hazard site evidence and allows signed-in volunteers to update only review decisions and image URLs.

The initial migration creates `hazards` and `hazard_warnings`, enables row level security, and inserts three repeatable sample hazard records for Colombo, Kandy, and Matara. Migration five adds four more sample citizen reports with mixed review outcomes. Each hazard has a `review_status` of `pending_review`, `accepted`, or `rejected`, plus an optional `image_url`. The ground reports page reads reports from Supabase and lets signed-in volunteers add an image URL or save a review decision. The assessment workflow lists only active hazards accepted by community volunteers. To change a decision in Supabase, update the `review_status` field, for example: `update public.hazards set review_status = 'accepted' where id = '<hazard-uuid>';`. Active hazard records are publicly readable; issued warnings are publicly readable; creating warnings requires an authenticated user. Chosen distribution channels are stored in each warning's `channels` array. The app saves drafts and issued warning records, but does not send them to push, SMS, or siren gateways.
